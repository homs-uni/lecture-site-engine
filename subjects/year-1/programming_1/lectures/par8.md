## الجزء الأول: ملخص منظم (اقرأ قبل المحاضرة!)

### 📍 عن هذه المحاضرة
> هذه المحاضرة تكمل موضوع التوابع (Functions) وتشرح كيف تتصرف المتحولات داخل التوابع، وكيف يتعامل `C++` مع الأرقام العشوائية.

### 🎯 ستتعلم
- **المتحول الساكن `static`** — متحول يحتفظ بقيمته بين استدعاءات التابع الواحد بدل أن يُعاد تصفيره في كل مرة.
- **مجال الرؤية (Scope)** — من يستطيع "رؤية" متحول معين، ولماذا التابع مجال مستقل بحد ذاته.
- **التوابع الرياضية الجاهزة** — مثل `sqrt`, `pow`, `ceil`, `floor` الموجودة في مكتبة `cmath`.
- **ضبط شكل الخرج** — استخدام `setw` و`setprecision` للتحكم بمظهر الأرقام المطبوعة.
- **التوليد العشوائي** — كيف يولّد `rand` أرقاماً "شبه عشوائية"، ودور `srand(time(0))` في جعلها مختلفة بكل تشغيل.

### 📚 المتطلبات السابقة
- **تعريف التوابع الأساسي (`Functions 1`)** — لازم تعرف كيف تكتب تابعاً، وكيف تمرر له وسائط (`parameters`)، وكيف يُعيد قيمة (`return`).
- **المتحولات العامة والمحلية** — الفرق بين `global variable` و `local variable` مطلوب فهمه قبل الدخول في `static` ومجالات الرؤية.
- **حلقة `for`** *(شرح زيادة للفهم)* — تُستخدم في أمثلة هذه المحاضرة (مثال النرد)، فمعرفتها المسبقة تسهّل المتابعة.

### 💡 الأفكار الرئيسية
1. **المتحول الساكن (`static`):** يُهيَّأ مرة واحدة فقط عند أول استدعاء للتابع، ثم يحتفظ بقيمته عبر كل الاستدعاءات اللاحقة — هذا يختلف جذرياً عن المتحول المحلي العادي الذي يُعاد إنشاؤه من الصفر في كل استدعاء.
2. **استقلالية التابع كمجال رؤية:** التابع لا يرى متحولات التابع الذي استدعاه، وهذه ليست مصادفة بل ميزة أمنية مقصودة تضمن أن سلوك التابع لا يتأثر بشيء غير الوسائط الممرَّرة له.
3. **العشوائية في الحاسوب وهمية (Pseudo-random):** لا يوجد "عشوائية حقيقية" داخل الحاسوب؛ `rand` يتبع معادلة رياضية معقدة، ولازم نغيّر نقطة انطلاقها (`seed`) عبر `srand(time(0))` كي لا نحصل على نفس النتائج في كل تشغيل.

### 🔗 كيف تتصل هذه المحاضرة بالمحاضرات الأخرى؟
- **السابقة:** محاضرة التوابع الأولى (`Functions 1`) علّمتك تعريف التابع واستدعاءه ← الآن نبني عليها لنفهم ماذا يحدث "داخل" التابع من ناحية المتحولات.
- **القادمة:** فهم مجال الرؤية والمتحولات الساكنة ضروري لاحقاً عند التعامل مع **المصفوفات (Arrays)** كما ظهر في مثال النرد `int dice[]={0,0,0,0,0,0}`، وكذلك عند بناء برامج أكبر متعددة التوابع والملفات.

### ⚠️ الأخطاء الشائعة الواجب تجنبها
- ❌ الاعتقاد أن `static int tmp=0;` تُعيد تصفير `tmp` في كل استدعاء — الصحيح أنها تُهيَّأ مرة واحدة فقط طوال عمر البرنامج.
- ❌ الاعتقاد أن التابع يستطيع رؤية متحولات محلية من التابع الذي ناداه (مثل `main`) — كل تابع مجال رؤية مستقل تماماً.
- ❌ نسيان استدعاء `srand(time(0))` قبل `rand()` والتفاجؤ بأن البرنامج يعطي نفس الأرقام "العشوائية" في كل تشغيل.

### 1. المتحولات الساكنة (Static Variables)

<!-- @render: {type: "code-first", visualization: "none", coverage: "100%"} -->
<!-- @connectivity: {prerequisite: "functions_1_basics"} -->

#### 📍 أين نحن الآن؟
نبدأ بفهم نوع خاص من المتحولات المحلية يُدعى `static`، يتصرف بشكل مختلف تماماً عن المتحول المحلي العادي.

#### ⬅️ الربط مع السابق
في محاضرة `Functions 1` تعلمت أن كل متحول محلي (`local variable`) يُنشأ من جديد في كل استدعاء للتابع ويُحذف عند انتهاء التابع. المتحول الساكن يكسر هذه القاعدة.

#### 💡 الفكرة الأساسية
**المتحول الساكن `static` يُهيَّأ عند أول استدعاء فقط، ثم يحتفظ بقيمته وتعديلاتها عبر كل الاستدعاءات التالية للتابع نفسه.**

#### 💻 الكود

```cpp
#include<iostream>
using namespace std;

int g = 0;                       // global variable, visible in whole file

int fun1(int p1, int p2) {
    static int tmp = 0;           // static local variable, initialized once
    tmp += p1 + p2;
    g   += p1 + p2;
    return tmp;
}

int main() {
    cout << fun1(1, 3) << "\n" << g << endl;   // first call
    cout << fun1(1, 3) << "\n" << g << endl;   // second call
    return 0;
}
```

**الناتج المتوقع:**
```
4
4
8
8
```

#### 📐 التعريف / الصيغة
> `static <type> <name> = <initial_value>;` — كلمة `static` قبل تعريف المتحول ضمن مجال رؤية (عادة داخل تابع) تجعله يحتفظ بقيمته بين الاستدعاءات المتتالية لنفس التابع.

#### 📖 الشرح
المتحول `tmp` مُعرَّف بكلمة `static` داخل `fun1`. عند أول استدعاء `fun1(1,3)`، يُهيَّأ `tmp` بالقيمة `0` (لأنها المرة الأولى فقط)، ثم يُضاف له `p1+p2 = 4`، فتصبح قيمته `4`. أما `g` فهو متحول عام (`global`) معرّف خارج أي تابع، لذلك هو مرئي على كامل الملف، ويُصبح أيضاً `4` بعد أول استدعاء.

عند الاستدعاء الثاني `fun1(1,3)`، **`tmp` لا يُعاد تصفيره إلى صفر** — بل يحتفظ بقيمته السابقة `4`، ثم يُضاف له `4` جديدة فتصبح `8`. وبالمثل يصبح `g` مساوياً `8` لأنه أيضاً يتراكم عبر الاستدعاءات (وهذا طبيعي لأنه `global` أصلاً، وليس بسبب `static`).

الفرق الجوهري: لو كان `tmp` متحولاً محلياً عادياً بدون `static`، لكانت قيمته تُعاد إلى `0` في بداية كل استدعاء، وكانت النتيجة ستكون `4, 4` وليس `4, 8`.

#### 💡 التشبيه:
> تخيل عداد كهرباء في بيتك — لا يُعاد تصفيره كل يوم، بل يستمر بالتراكم من حيث توقف.
> **وجه الشبه:** عداد الكهرباء = `tmp`، القراءة المتراكمة = القيمة المحفوظة بين الاستدعاءات.

#### 🎯 الملخص السريع
- `static` تُستخدم مع متحول محلي داخل تابع.
- تتم التهيئة مرة واحدة فقط، عند أول استدعاء.
- القيمة تبقى محفوظة وتتراكم عبر كل الاستدعاءات اللاحقة.
- يختلف هذا عن المتحول العام (`global`) رغم تشابه سلوك "البقاء"، لأن `static` هنا محصور برؤية داخل التابع فقط، بينما `global` مرئي بكل الملف.

#### 📚 التطبيق
تُستخدم المتحولات الساكنة لاحقاً في أي سيناريو يحتاج "عدّاد" أو "ذاكرة داخلية" لتابع معين، مثل عدّ عدد مرات استدعاء تابع معين دون الحاجة لمتحول عام يراه كل الملف.

### 2. توسعة في مجالات الرؤية (Scope Extension)

<!-- @render: {type: "code-first", visualization: "diagram", coverage: "100%"} -->
<!-- @connectivity: {prerequisite: "section_1"} -->

#### 📍 أين نحن الآن؟
بعد فهم كيف تتصرف قيمة المتحول عبر الزمن (`static`)، ننتقل لفهم "أين" يمكن لمتحول أن يُرى ضمن الكود.

#### ⬅️ الربط مع السابق
في القسم السابق استخدمنا مصطلح "مجال رؤية" (`scope`) بشكل ضمني عندما قارنّا `g` (المرئي في كل الملف) مع `tmp` (المرئي فقط داخل `fun1`). الآن سنُفصِّل هذا المفهوم بقواعد واضحة.

#### 💡 الفكرة الأساسية
**مجال الرؤية هو المساحة (غالباً بين قوسين `{ }`) التي يمكن ضمنها استخدام متحول معين؛ وكل تابع هو مجال رؤية مستقل بحد ذاته لا يرى مجالات التوابع الأخرى.**

#### 📐 التعريف / الصيغة
> **مجال الرؤية (Scope):** المنطقة من الكود التي يكون فيها المتحول معرَّفاً وقابلاً للاستخدام. يُعرَّف عادة بين قوسين `{ }`.
>
> **قواعد عامة:**
> 1. المتحول المعرَّف ضمن مجال معين يكون غير مرئي خارج هذا المجال.
> 2. مجالات الرؤية يمكن أن تتداخل (`nested`): متحولات المجال الأب مرئية ضمن مجال الابن، لكن العكس غير صحيح.
> 3. التابع مجال رؤية مستقل بحد ذاته — إذا استُدعي تابع من داخل مجال آخر، فإن هذا التابع لا يرى متحولات المجال الذي استدعاه.

#### 2.1. القاعدة الأولى والثانية: التعريف داخل الكتلة وتداخل المجالات

#### 💻 الكود

```cpp
#include<iostream>
using namespace std;

int main() {
    for (int i = 0; i < 10; i++) {
        cout << i % 2 << endl;     // ✔️ correct: i visible inside the loop block
    }
    cout << i;                     // ❌ compiler error: i not visible here
}
```

**مقابل النسخة الصحيحة:**

```cpp
#include<iostream>
using namespace std;

int main() {
    int i;                          // i defined in the outer (main) scope
    for (i = 0; i < 10; i++) {
        cout << i % 2 << endl;      // ✔️ correct
    }
    cout << i;                       // ✔️ correct: i still visible here
}
```

#### 📖 الشرح
في المثال الأول، المتحول `i` عُرِّف داخل قوسي حلقة `for` نفسها (`for(int i=0; ...)`)، لذلك مجال رؤيته محصور بداخل هذه الحلقة فقط. أي محاولة لاستخدامه بعد إغلاق قوس الحلقة `}` تسبب خطأ في الترجمة (`compiler fails`) لأن `i` غير موجود أصلاً في مجال `main` الخارجي.

في المثال الثاني، عُرِّف `i` خارج الحلقة، ضمن مجال `main` مباشرة. بما أن مجال حلقة `for` هو "ابن" لمجال `main` الأب، فإن `i` (وهو متحول الأب) يبقى مرئياً داخل حلقة `for` وأيضاً بعد انتهائها، لأنه أصلاً جزء من مجال `main` الأكبر.

هذا يوضح القاعدة: **متحولات المجال الأب مرئية داخل مجال الابن (كالحلقة)، لكن متحول عُرِّف داخل الابن لا يبقى مرئياً بعد خروجنا من ذلك الابن.**

- المتحول غير مرئي خارج المجال الذي عُرِّف فيه.
- مجالات الرؤية يمكن أن تتداخل (مثل `for` داخل `main`).
- متحولات مجال الأب مرئية ضمن مجال الابن، لكن العكس غير صحيح.

#### 💡 التشبيه:
> تخيل غرفة داخل بيت — كل ما في البيت (الأب) يمكن رؤيته من داخل الغرفة (الابن)، لكن ما تضعه داخل الغرفة فقط لا يظهر لبقية البيت إن كانت الغرفة مغلقة (خارج نطاقها).
> **وجه الشبه:** البيت = مجال main، الغرفة = مجال for، أغراض الغرفة الخاصة = متحول i المعرف داخلها فقط.

#### 2.2. القاعدة الثالثة: التابع مجال رؤية مستقل

#### 💻 الكود

```cpp
int sum(int a, int b) {
    int x = a + b;
    c = 1;              // ❌ compiler fails: c is not visible here
    return x;
}

int main() {
    cout << i;           // (context from previous slide — i undefined here too)
    int c = 10;
    cout << sum(1, 4);
    return 0;
}
```

#### 📖 الشرح
هنا التابع `sum` يحاول استخدام المتحول `c` مباشرة (`c = 1;`)، رغم أن `c` معرَّف داخل `main` (التابع الذي استدعى `sum`). هذا الكود لا يُترجم أبداً — لأن `sum` **مجال رؤية مستقل تماماً** عن `main`، ولا يرى أي متحول محلي معرَّف داخل `main` مهما كان اسمه.

السبب الأعمق مرتبط بطريقة عمل التوابع: لا يوجد شرط يُلزم التابع أن يُستدعى من مكان معين — يمكن استدعاؤه من تابع آخر، أو حتى من ملف مختلف بالكامل. لذلك، **لا يمكن للمترجم أن يعرف مسبقاً "من الذي سيستدعي هذا التابع"**، وبالتالي لا يمكنه تحديد أي متحولات ستكون متاحة من "مجال المستدعي" — فيُقرر ببساطة ألا يسمح لأي تابع برؤية متحولات محلية لتابع آخر إطلاقاً.

هذه القاعدة ليست قيداً مزعجاً بل **ميزة أمنية مهمة**: بما أن التابع لا يمكنه تعديل متحولات خارج نطاقه أو تغيير سلوكه بناءً على بيئة الاستدعاء، فإن كل ما يستطيع المبرمج التأثير به هو **القيم المُمرَّرة كوسائط**. هذا يضمن استقرار الأداء بمبدأ: **دخل محدد => خرج محدد** — أي أن نفس الوسائط تنتج دائماً نفس النتيجة، بغض النظر عمّن استدعى التابع أو من أين.

#### 🤔 تفعيل الفهم (اسأل نفسك):
> **سؤال:** لو استطاع `sum` أن يرى ويُعدِّل متحول `c` في `main` مباشرة، ماذا سيحدث لو استدعيت `sum` من تابع آخر ليس فيه أي متحول اسمه `c`؟
> **لماذا هذا مهم؟** لأن هذا يوضح استحالة تصميم لغة تسمح بذلك بشكل موثوق — ولهذا اختار مصممو اللغة عزل كل تابع كمجال مستقل.

#### 🎯 الملخص السريع
- التابع لا يرى متحولات التابع الذي استدعاه.
- السبب: لا يمكن تحديد "مجال الاستدعاء" مسبقاً لأن التابع قد يُستدعى من أي مكان (حتى من ملفات أخرى).
- هذه العزلة تضمن أمان الأداء: التابع يتأثر فقط بالوسائط الممرَّرة له صراحة.

#### 📚 التطبيق

### 4. التوليد العشوائي (Random Number Generation)

<!-- @render: {type: "code-first", visualization: "diagram", coverage: "100%"} -->
<!-- @connectivity: {prerequisite: "section_3"} -->

#### 📍 أين نحن الآن؟
ننتقل الآن لموضوع مهم جداً في علوم الحاسب: كيف نولّد أرقاماً عشوائية، ولماذا هذا مهم خصوصاً في أمن المعلومات.

#### ⬅️ الربط مع السابق
`rand` هو تابع جاهز آخر (تماماً كتوابع `cmath`)، لكنه موجود في مكتبة مختلفة هي `stdlib`.

#### 💡 الفكرة الأساسية
**`rand` يولّد عدداً "شبه عشوائي" بين `0` و`RAND_MAX`، ونتحكم بمجاله عبر `%` و`-`، بينما `srand(time(0))` يضمن نتائج مختلفة في كل تشغيل للبرنامج.**

#### 4.1. التابع `rand` وضبط المجال

#### 📐 التعريف / الصيغة
> `rand()` — لا يتطلب أي وسيط، ويعيد عدداً صحيحاً بين `0` و `RAND_MAX` (قيمة `RAND_MAX` تختلف من نسخة مترجم لأخرى، لكنها على الأقل `32767`).
>
> **لحصر الخرج ضمن مجال `[0, n-1]`:** نستخدم `rand() % n`.
> **لتحصر الخرج ضمن مجال يبدأ من رقم آخر غير الصفر:** نجمع أو نطرح بعد الباقي، مثل `rand() % 11 - 5` للحصول على مجال `[-5, 5]`.

#### 💻 الكود

```cpp
#include<iostream>
#include<stdlib.h>
using namespace std;

int main() {
    cout << rand() << endl;          // raw random number between 0 and RAND_MAX
    cout << rand() % 7 << endl;      // random number in range [0, 6]
    cout << rand() % 11 - 5 << endl; // random number in range [-5, 5]
    return 0;
}
```

**الناتج المتوقع (تشغيل أول):**
```
1804289383
4
1
```

**الناتج المتوقع (تشغيل ثانٍ — بدون `srand`):**
```
1804289383
4
1
```

#### 📖 الشرح
لاحظ أن العدد `rand()%7` يقع دائماً ضمن المجال `[0,6]` — وذلك لأن باقي قسمة أي عدد على `7` يقع حتماً بين `0` و`6` شاملاً (7 قيم ممكنة). هذه هي الفكرة الأساسية وراء استخدام `%` للتحكم بمجال العشوائية: **باقي القسمة على `n` يقع دائماً بين `0` و `n-1`.**

المفاجأة هنا (والتي ستُشرح في القسم التالي) أن **نفس الأرقام بالضبط ظهرت في التشغيلين الأول والثاني** رغم أننا نتوقع أن تكون "عشوائية"! هذا ليس خطأ بل سلوك متوقع سنفهم سببه الآن.

#### 🤔 تفعيل الفهم (اسأل نفسك):
> **سؤال:** إذا كان برنامج عشوائي يعطي نفس النتيجة بالضبط عند كل تشغيل، هل هو حقاً "عشوائي"؟
> **لماذا هذا مهم؟** لأن الجواب يقودنا لفهم أن الحاسوب لا يملك عشوائية حقيقية، بل يتبع نمطاً معقداً جداً لكنه ثابت.

#### 4.2. لماذا تتكرر نفس النتائج؟ ودور `srand(time(0))`

#### 📖 الشرح
في الطبيعة، لا يوجد شيء "عشوائي بحت" — كل شيء يتبع لقاعدة أو نمط، مهما كان هذا النمط معقداً. وحتى داخل الحاسوب، تابع `rand` يتبع معادلة رياضية معقدة لتوليد قيم "شبه عشوائية" (Pseudo-random). وكأي معادلة رياضية، فهي تحتاج **نقطة بداية (seed)**، وبما أن نقطة البداية هذه ثابتة افتراضياً، فإن استدعاء `rand` سيُنتج دائماً **نفس تسلسل الأرقام** بالضبط، بغض النظر عن عدد مرات تشغيل البرنامج.

بناءً على ذلك، يجب أن نُغيِّر نقطة البداية هذه عند بدء البرنامج حتى تتغير النتيجة في كل استدعاء (أي في كل تشغيل جديد). هنا يأتي دور تابعين:
- **`time(0)`:** يعيد القيمة الحالية لوقت النظام، مخزَّنة كثوانٍ ابتداءً من الساعة `00:00` بتاريخ 1 كانون الثاني (يناير) 1970 (يُعرف هذا بـ `Unix Time`). وبما أن هذه القيمة تتغير باستمرار (كل ثانية)، فإنها مختلفة في كل تشغيل جديد للبرنامج.
- **`srand(seed)`:** يستخدم القيمة الممرَّرة له كنقطة انطلاق جديدة لمعادلة `rand`.

بجمع الاثنين معاً: `srand(time(0));` نحصل في كل تشغيل على نقطة بداية مختلفة (لأن الوقت يتغير باستمرار)، وبالتالي نحصل على تسلسل أرقام مختلف في كل مرة.

#### 💻 الكود

```cpp
#include<iostream>
#include<stdlib.h>
using namespace std;

int main() {
    srand(time(0));                  // seed rand() with the current system time
    cout << rand() << endl;
    cout << rand() % 7 << endl;
    cout << rand() % 11 - 5 << endl;
    return 0;
}
```

#### 4.3. مثال تطبيقي: محاكاة رمي النرد (Dice Simulation)

#### 📍 أين نحن الآن؟
لنطبّق كل ما تعلمناه (تابع، متحول عام، عشوائية، حلقات) في مثال واحد متكامل.

#### 💻 الكود

```cpp
#include<iostream>
#include<stdlib.h>
using namespace std;

int dice[] = {0, 0, 0, 0, 0, 0};   // array holding count of each face (1..6)

void throwDice() {
    int diceValue = rand() % 6;    // random value between 0 and 5
    dice[diceValue]++;             // increment counter for that face
}

int main() {
    srand(time(0));                 // new seed each run
    for (int i = 0; i < 100000; i++)
        throwDice();                 // simulate 100000 dice throws

    cout << "The dice\n";
    for (int i = 0; i < 6; i++)
        cout << "\t" << i + 1 << " " << dice[i] << endl;  // print count per face

    return 0;
}
```

```

    1 16777
    2 16668
    3 16626
    4 16710
    5 16516
    6 16703
```

#### شرح كل سطر:
1. `int dice[] = {0,0,0,0,0,0};` → تعريف مصفوفة عامة *(شرح زيادة للفهم: المصفوفات ستُشرح بالتفصيل في محاضرة قادمة)* — تُخزّن عدد مرات ظهور كل وجه من أوجه النرد (6 خانات للأوجه 1 إلى 6).
2. `void throwDice()` → تابع لا يُعيد قيمة (`void`)، يمثل "رمية نرد واحدة".
3. `int diceValue = rand() % 6;` → نحصل على عدد عشوائي بين `0` و`5` يمثل وجه النرد الناتج (مطروحاً منه 1، لأن فهرسة المصفوفة تبدأ من الصفر).
4. `dice[diceValue]++;` → نزيد عداد الوجه المطابق بمقدار 1 في كل رمية.
5. `srand(time(0));` → ضبط نقطة انطلاق مختلفة في كل تشغيل (كما شرحنا في القسم السابق).
6. `for(int i=0;i<100000;i++) throwDice();` → تكرار عملية الرمي 100000 مرة لمحاكاة عدد كبير من التجارب.
7. الحلقة الثانية `for(int i=0;i<6;i++)` → تمر على الأوجه الستة وتطبع عدد مرات ظهور كل واحد منها.

#### 📖 الشرح
هذا المثال يجمع بين كل مفاهيم المحاضرة: **مصفوفة عامة** (`dice`) مرئية من داخل `throwDice` (لأنها معرَّفة خارج أي تابع، فهي عامة `global` مثل `g` في القسم الأول)، **تابع مستقل** (`throwDice`) يُعدِّل هذه المصفوفة العامة عبر استدعائه 100000 مرة، و**توليد عشوائي** مضبوط بـ `srand(time(0))` ليعطي نتائج مختلفة كل تشغيل، ثم `%6` لحصر النتيجة ضمن 6 قيم ممكنة (أوجه النرد).

لاحظ في الناتج أن كل وجه ظهر بمعدل قريب جداً من `100000/6 ≈ 16666` مرة — وهذا منطقي لأن كل وجه من أوجه النرد له احتمال متساوٍ (`1/6`) بالظهور.

#### 🎯 الملخص السريع
- المصفوفة العامة `dice` تُستخدم كذاكرة مشتركة بين `main` و`throwDice`.
- `rand() % 6` يحاكي وجه نرد عشوائي.
- تكرار العملية 100000 مرة يعطي توزيعاً متقارباً بين الأوجه الستة، مما يؤكد عدالة التوزيع العشوائي.

- ✅ **الخيار ب:** يكفي ضبط نقطة الانطلاق مرة واحدة في بداية البرنامج ليعمل `rand` بشكل مختلف في كل تشغيل جديد للبرنامج.
- ❌ **الخيار أ:** استدعاؤها قبل كل `rand()` قد يُعيد نفس القيمة الزمنية (إن حدثت خلال نفس الثانية) فيُفسد التنويع بدل أن يحسّنه.
- ❌ **الخيار ج:** في نهاية البرنامج لن يكون لها أي تأثير على الأرقام المولَّدة أثناء التنفيذ.
- ❌ **الخيار د:** بدونها، النتائج تتكرر في كل تشغيل، وهذا عكس الهدف من العشوائية.

### السؤال 15 (hard)

في مثال محاكاة النرد، لماذا كانت `dice` متحولاً عاماً وليست محلية داخل `main`؟

أ) لأن المصفوفات لا يمكن أن تكون محلية أبداً
ب) ليكون التابع `throwDice` قادراً على الوصول إليها وتعديلها مباشرة، بما أنه لا يمكنه رؤية متحولات main المحلية
ج) لتسريع البرنامج فقط
د) لتقليل استهلاك الذاكرة

**الإجابة الصحيحة: ب**

**التعليل:**
- ✅ **الخيار ب:** بما أن `throwDice` تابع مستقل لا يرى متحولات `main`، جعل `dice` عامة (`global`) هو الحل الذي يسمح له بالوصول إليها وتعديلها مباشرة.
- ❌ **الخيار أ:** المصفوفات يمكن أن تكون محلية بلا مشاكل في حالات أخرى.
- ❌ **الخيار ج:** لا علاقة مباشرة بالسرعة؛ السبب متعلق بمجال الرؤية.
- ❌ **الخيار د:** لا علاقة للأمر باستهلاك الذاكرة في هذا السياق.

### السؤال 16 (medium)

بعد محاكاة 100000 رمية نرد، لماذا كان عدد ظهور كل وجه قريباً جداً من 16666؟

أ) لأن البرنامج يحتوي على خطأ برمجي
ب) لأن كل وجه من أوجه النرد له احتمال متساوٍ (1/6) بالظهور، وبعدد تجارب كبير تقترب النتائج من هذا التوزيع المتساوي
ج) لأن `rand()` مصمم ليعطي دائماً هذا الرقم بالضبط
د) لأن `%6` تجبر الأرقام على أن تكون متساوية تماماً في كل تجربة

**الإجابة الصحيحة: ب**

**التعليل:**
- ✅ **الخيار ب:** هذا سلوك متوقع إحصائياً — كلما زاد عدد التجارب، اقترب التوزيع الفعلي من التوزيع الاحتمالي النظري المتساوي بين الأوجه الستة.
- ❌ **الخيار أ:** النتيجة طبيعية تماماً ولا تدل على أي خطأ.
- ❌ **الخيار ج:** `rand()` لا يعيد قيماً ثابتة، بل عشوائية تتقارب إحصائياً فقط مع عدد كبير من التكرارات.
- ❌ **الخيار د:** `%6` تحصر المجال فقط بين `0` و`5`، لكنها لا تفرض تساوياً في كل تجربة فردية، بل التقارب يظهر فقط عند تكرار كبير.

## الجزء الثالث: بطاقات سؤال وجواب (Q&A Cards)

### البطاقة 1
**Q1:** متى تُهيَّأ قيمة المتحول الساكن `static`؟
**A:** عند أول استدعاء للتابع فقط، وليس في كل استدعاء لاحق.

### البطاقة 2
**Q2:** ما الفرق بين متحول `static` ومتحول `global`؟
**A:** كلاهما يحتفظ بقيمته طوال عمر البرنامج، لكن `static` محصور الرؤية داخل التابع الذي عُرِّف فيه، بينما `global` مرئي في كل الملف.

### البطاقة 3
**Q3:** أين يُعرَّف مجال الرؤية عادة في `C++`؟
**A:** بين قوسين `{ }`.

### البطاقة 4
**Q4:** هل يمكن لمجال ابن (مثل حلقة `for`) رؤية متحول مجال الأب (مثل `main`)؟
**A:** نعم، متحولات مجال الأب مرئية ضمن مجال الابن.

### البطاقة 5
**Q5:** هل يمكن لمجال الأب رؤية متحول عُرِّف داخل مجال الابن؟
**A:** لا، لا يمكن ذلك؛ المتحول يبقى محصوراً داخل المجال الذي عُرِّف فيه فقط.

### البطاقة 6
**Q6:** لماذا لا يستطيع التابع رؤية متحولات التابع الذي استدعاه؟
**A:** لأنه لا يمكن تحديد مسبقاً من أين سيُستدعى التابع (حتى من ملفات أخرى)، فيُعامل كل تابع كمجال رؤية مستقل بالكامل.

### البطاقة 7
**Q7:** ما الميزة الأمنية لعزل مجال رؤية التوابع؟
**A:** تضمن أن التابع يتأثر فقط بالوسائط الممرَّرة إليه، مما يحقق مبدأ "دخل محدد => خرج محدد".

### البطاقة 8
**Q8:** ما الفرق بين `ceil` و`floor`؟
**A:** `ceil` تقرّب دائماً للأعلى (أصغر عدد صحيح أكبر أو يساوي)، بينما `floor` تقرّب دائماً للأسفل (أكبر عدد صحيح أصغر أو يساوي).

### البطاقة 9
**Q9:** ما وظيفة `setw(n)` في الخرج؟
**A:** تضبط عرض حقل الطباعة القادم بحيث يكون بعرض `n` من الفراغات، لأغراض المحاذاة.

### البطاقة 10
**Q10:** كيف نحصر ناتج `rand()` ضمن مجال `[0, n-1]`؟
**A:** باستخدام `rand() % n`.

### البطاقة 11
**Q11:** ما وظيفة `srand(time(0))`؟
**A:** تضبط نقطة انطلاق (`seed`) جديدة لمعادلة `rand` بناءً على الوقت الحالي، لضمان نتائج مختلفة في كل تشغيل للبرنامج.

### البطاقة 12
**Q12:** لماذا تُسمى عشوائية `rand` بـ "شبه عشوائية" (Pseudo-random)؟
**A:** لأنها في الحقيقة نتيجة معادلة رياضية معقدة وثابتة، وليست عشوائية حقيقية؛ فقط تغيير نقطة الانطلاق (`seed`) هو ما يجعل النتائج تبدو مختلفة في كل مرة.

### البطاقة 13
**Q13:** في مثال النرد، لماذا كانت مصفوفة `dice` معرَّفة خارج كل التوابع؟
**A:** لتكون متحولاً عاماً (`global`) يستطيع التابع `throwDice` الوصول إليه وتعديله، بما أنه لا يستطيع رؤية متحولات `main` المحلية.

### البطاقة 14
**Q14:** ما القيمة الدنيا المضمونة لـ `RAND_MAX`؟
**A:** `32767` على الأقل (قد تكون أكبر حسب نسخة المترجم).

## الجزء الرابع: ورقة المراجعة السريعة

### 🔑 خريطة التكامل (مختصرة)
| المفهوم | يعتمد على | يُستخدم لاحقاً في |
| --- | --- | --- |
| المتحول الساكن (`static`) | فهم المتحول المحلي والعام | العدّادات الداخلية للتوابع، تتبع الحالة بين الاستدعاءات |
| مجالات الرؤية (`scope`) | تعريف التوابع والمتحولات | تنظيم برامج متعددة التوابع والملفات |
| التوابع الرياضية (`cmath`) | استدعاء التوابع الأساسي | الحسابات الهندسية والعلمية |
| ضبط الخرج (`iomanip`) | `cout` الأساسي | طباعة تقارير وجداول منظمة |
| التوليد العشوائي (`rand`/`srand`) | حلقات + توابع + مصفوفات مبدئياً | محاكاة الألعاب، التشفير، الاختبارات الإحصائية |

### 🔑 القواعد الذهبية
| # | القاعدة |
| --- | --- |
| 1 | `static` تُهيَّأ مرة واحدة فقط عند أول استدعاء، وتحتفظ بقيمتها لاحقاً. |
| 2 | كل تابع مجال رؤية مستقل — لا يرى متحولات التابع الذي استدعاه أبداً. |
| 3 | متحول مجال الأب مرئي ضمن مجال الابن، لكن العكس غير صحيح. |
| 4 | `rand() % n` يحصر الناتج ضمن `[0, n-1]`. |
| 5 | استدعِ `srand(time(0))` مرة واحدة فقط في بداية البرنامج لضمان نتائج مختلفة في كل تشغيل. |

### 🔑 جداول مرجعية سريعة

| المصطلح | التعريف القصير |
| --- | --- |
| `static` | متحول محلي يُهيَّأ مرة واحدة ويحتفظ بقيمته بين الاستدعاءات |
| `global` | متحول مرئي في كل الملف، خارج أي تابع |
| `scope` | المساحة التي يكون فيها المتحول قابلاً للاستخدام |
| `RAND_MAX` | أكبر قيمة ممكنة يعيدها `rand()` (لا تقل عن 32767) |
| `seed` | نقطة الانطلاق التي تبدأ منها معادلة توليد الأرقام العشوائية |

| المعيار | `static local` | `global` |
| --- | --- | --- |
| **مكان الرؤية** | داخل التابع فقط | كل الملف |
| **التهيئة** | مرة واحدة عند أول استدعاء | مرة واحدة عند بدء البرنامج |
| **بقاء القيمة** | نعم، بين الاستدعاءات | نعم، طوال عمر البرنامج |

| المعيار | `ceil` | `floor` | `round` |
| --- | --- | --- | --- |
| **اتجاه التقريب** | دائماً للأعلى | دائماً للأسفل | حسب قاعدة التقريب الرياضي |
| **مثال (20.1)** | 21 | 20 | 20 |
| **مثال (20.9)** | 21 | 20 | 21 |
